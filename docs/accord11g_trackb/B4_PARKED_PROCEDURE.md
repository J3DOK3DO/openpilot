# B4 parked source diagnostic procedure

This procedure is only for a parked, non-production source/host diagnostic. The **audit program itself** does not open vehicle, Panda, CAN, USB, SPI, UDS, Params, route, telemetry, VIN or network interfaces. On a connected comma, ordinary **Track A services may still operate**; this program does not disable or modify them. Factory ACC remains the only longitudinal owner.

1. Only after this branch is published on GitHub, copy the exact published release commit SHA from GitHub into `RELEASE_COMMIT`; do not compute `HEAD` in the checkout and treat it as a trusted pin. In the parked, offroad source checkout, run `python3 scripts/accord11g_trackb_parked_audit.py --root "$PWD" --expected-head RELEASE_COMMIT` (for example after `cd /data/openpilot` on comma). `RELEASE_COMMIT` must be exactly 40 lowercase hexadecimal characters. This direct Python command does **not** launch Dom's host-build wrapper, manager or pandad.
2. Review the JSON printed to stdout. It records source SHA256 values, source git SHA when safely obtainable, host architecture/OS, `/AGNOS` presence and one unambiguous marker if available, boolean process presence for `manager`, `pandad`, and `controlsd`, and expected source-directory existence. It does not emit process command lines or vehicle data.
3. To retain a result, choose an approved confidential location and explicitly add `--output /approved/location/trackb-parked-audit.json`. The result file is created/restricted to mode 0600. Do not place results in route, cloud, or public issue locations without the applicable data review.
4. Verify nonactuation from the implementation: it imports only Python standard-library modules; reads files and numeric `/proc/*/comm`; uses read-only `git rev-parse HEAD` and `git status --porcelain --untracked-files=no` to verify both commit identity and tracked-source cleanliness; has no Panda import, CAN/USB/SPI/UDS/Params API, network API, shell command, or manager integration. Review the new native tests as part of that check.

Fail the parked audit if a selected source file is missing, the checkout is not the trusted real repository structure, output cannot be protected, the audit accesses a forbidden interface, or its command-free behavior cannot be verified. Without `--expected-head`, with a nonmatching/unavailable git HEAD, a modified tracked checkout, unavailable/incomplete proc data, a non-ARM64 host, or a missing AGNOS version marker, treat the result as `UNKNOWN`, never a pass. The audit accepts no operator-selected proc root; test-only synthetic proc roots are injected by the native tests. A PASS means only that this limited source/host audit was complete; it is never a readiness-to-drive or vehicle-qualification conclusion.

If this source branch is installed on a comma, preserve the known-good installation and verified rollback path, remain parked/offroad, and do not use it as evidence of custom longitudinal capability or permission to drive. The branch adds no automatic Track B service or actuation, must not flash firmware or change factory ACC/CMBS/AEB ownership, and does not prove ARM64/device compatibility until the actual installation is independently checked.
