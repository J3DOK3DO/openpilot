## Measured legacy ABI inventory

`abi_inventory.json` in `D/evidence/C8_2_C8_OFFLINE_20261115` records 24 exact paths, sizes, SHA-256 values and symlink flags for **both** old roots. Nineteen present files hash identically in both: loader, glibc, libstdc++, SSL/crypto, USB, ZMQ, OpenCL, Adreno EGL/GLES, Python 3.12, z/zstd/ffi, KGSL and camera headers, OpenCL/EGL headers, and vendor EGL. Five selected paths are absent in both: `libcapnp.so.1` at two locations, Cap'n Proto headers at two locations, and `libparams_c.so`. These absences do not show missing production libraries: Cap'n Proto is supplied by the builder and `libparams_c.so` is a build output. They do prevent calling this a complete product ABI inventory. **Pairwise old-root consistency is confirmed; comparison to target 20.5.2 is impossible without its bytes.** Historical TrackAB device-vs-image comparison measured 17 files on 19.8.1; it is not C8 device proof.

## Offline builder inventory

Three existing ARM64 images were probed with `--pull never --network none --read-only --cap-drop ALL` and no device binds. `dom7-trackb-arm64:20261030` (`b1c49f3a…`) and `ghcr.io/commaai/openpilot-base-aarch64:latest` (`b3562774…`) have Cap'n Proto CLI 1.0.1; `starpilot-larch64-builder:latest` (`3cc10a4b…`) has 1.0.2 and fails the Dockerfile's 1.0.1 requirement. All have Python 3.12.3 and AArch64 GCC/Clang but lack SCons, acados, capnproto, ffmpeg, json11, ncurses, zstd and libusb Python imports by themselves. The old TrackAB ARM64 venv has locked SCons 4.11.1, acados 0.2.2.post103, capnproto 1.0.1.post103, ffmpeg 7.1.0.post103, json11 20170411.0.post103; a locked nanobind 3.1.0 package is in the local uv archive. These packages were mounted read-only for a root preflight and were not installed globally or copied into this checkout. Package presence does not establish 20.5.2 runtime ABI.

The supported `laptop_device_build.sh` setup extracts and **repairs/sanitizes** a writable sysroot, and its build mode scrubs checkout outputs and can touch `prebuilt`. Those modes were not invoked against legacy data. For future setup, obtain the owner's trusted 20.5.2 image through an authorized offline channel; check the decompressed sparse hash against `hash`, expand and check the raw image against `hash_raw` in scratch space with adequate reserve, record its `/VERSION` and 15–30 ABI library hashes, and extract into a **new** isolated sysroot. Then create a disposable `/tmp` build tree, resolve exact locked ARM64 packages from verified cache, use read-only image and source binds, run the root preflight and bounded build, and compare target ELF dependencies against that new sysroot. Never edit a legacy sysroot or represent a diagnostic bind as a matched target.
