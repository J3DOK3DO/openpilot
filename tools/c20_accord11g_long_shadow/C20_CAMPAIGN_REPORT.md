## Admission and replay

`admission.py` validates exact 11G hybrid identity, route and trace binding, radar/camera/brake firmware, software and DBC SHA-256 provenance, declared units, monotonic time, required signals with per-signal timestamps, lead validity and freshness, and overrides. Statuses are `VERIFIED_MATCH`, `COMPATIBLE_BUT_UNVERIFIED`, `MISMATCH`, `INSUFFICIENT_EVIDENCE`. The only public path to `RECORDED_VERIFIED` performs exact comparison with a separately supplied authenticated reference and an independently obtained reference digest. The program cannot itself prove that a reference issuer measured the claimed vehicle. An unrelated route or unknown ECU firmware is rejected or left unverified.

No authentic route, ECU firmware inventory, software/DBC provenance, or independent reference for this specific car was available in this worktree. The committed example manifest deliberately retains `UNVERIFIED` values. Only the invented five-row fixture was replayed, with mode `SIMULATED`; no recorded Accord benchmark or vehicle improvement claim exists.

The replay compares two behavioral references on identical rows. It reports headway, acceleration-demand error, reference jerk, hold decisions, lead transitions, standstill, driver override, lead freshness, and reasons. It applies a numerical floor to observed braking in the synthetic reference and resets hold on lead-ID replacement. These calculations do not prove actual braking or prevent a runtime hazard because no runtime path exists.

Git scope review checked only new research files were staged and committed.

Fault challenge: independent review found that a caller could originally force the `RECORDED_VERIFIED` label by passing a string into the comparison API; this was fixed by making the public `compare` simulated-only and performing admission inside `compare_recorded`. The review also found missing per-signal freshness; source timestamps for eight essential signals are now required and checked. A plausible forged manifest plus reference could still pass structural checks if the purported independent hash is also fabricated; external custody/authentication is essential. Timestamps do not certify sensor synchronization. Confidence is parsed but cannot prove radar identity. A behavioral comparator can understate real tracking and braking error because it lacks full C19/C6 native dependencies, actuator delay, controller saturation, and recorded feedback. The paired MVL wind and gas learning state is historically tied to control and is unsuitable for direct Accord adaptation. Tests are synthetic and cannot prove AEB/CMBS preservation or actual braking. Factory radar ownership, startup relay sequencing, Panda restrictions, and independent on-car safety evidence remain release blockers. **No vehicle, connected Comma/Panda device, production runtime, prebuilt receipt, or native artifact was modified.**
