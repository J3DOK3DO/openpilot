# R25 offline installation candidate recipe

This is a **no-actuation release recipe**. The current tree is source-only and **not installable**. A host operator performs the exact commit and independent reviews; no command below pushes, changes a device, or enables longitudinal control.

1. From the C20 worktree, run `PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s tools/c20_accord11g_long_shadow/tests -q` and `PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest tools.ci.tests.test_r25 -v`. Run `python3 -B -m tools.c20_accord11g_long_shadow.r25_gate`, `python3 -B -m tools.c20_accord11g_long_shadow.r25_package candidate`, and `git diff --check`. Record their exact output. The gate must retain Path B2 `NO_GO`, device `NOT_RUN` and physical `UNVERIFIED`.
2. Review the diff and have the host operator commit it. Recheck exact `git rev-parse HEAD` and clean `git status --porcelain --untracked-files=all`. Do not use a tree, archive or receipt from before that commit.
3. On a qualified build host, record the clean source commit as `source_revision`, obtain the required AArch64 toolchain, run an actual SCons product build, and verify the QCOM compiled model artifacts and installer dependencies. The build must not modify Panda safety or active control gates. Preserve actual build logs. Do not synthesize build evidence from existing ELF files.
4. Refresh `prebuilt.json` using the existing product receipt workflow **only after** the actual product build, then commit the refreshed receipt with built artifacts and review the final exact commit. Only build artifacts and `prebuilt`/`prebuilt.json` may differ from `source_revision`. Run `tools/ci/check_prebuilt_receipt.py --revision HEAD`. A refreshed receipt alone does not prove a build. Attest the actual build in a separate JSON receipt with exact schema keys `schema_version`, `source_revision`, `revision`, `build_system`, `build_exit`, `architecture`, `artifacts_sha256`; `revision` is the final commit, `schema_version=1`, `build_system="scons"`, `build_exit=0`, `architecture="aarch64"`, and hashes cover all paths named in `r25_package.py`.
5. When the gate and package candidate both accept the exact clean commit, use `python3 -B -m tools.c20_accord11g_long_shadow.r25_package build --build-receipt /path/to/actual-build-receipt.json --output /tmp/c20-r25-candidate.tar`, then `python3 -B -m tools.c20_accord11g_long_shadow.r25_package verify --output /tmp/c20-r25-candidate.tar`. This archive is an offline package for independent review; the package code does not perform installation and does not assert device readiness.
6. On-device and physical acceptance require separate owner-controlled procedures and evidence. No active longitudinal B2 is included. Any proposed B2 path needs a separate controller, radar, Panda safety, hardware and vehicle-specific qualification campaign.

For a parked-device synthetic ARM64 MPC smoke check, after a genuinely qualified installation, manually invoke `python3 -B -m openpilot.starpilot.longitudinal.c20_shadow_smoke --synthetic-native-smoke --cycles 2`. It executes the original product LongitudinalMpc and native solver only against invented fixed scalar inputs; no Cereal subscription or control output exists in this entry point. Require `LOCAL_NUMERICAL_EXECUTION`, two actual solve returns of zero, finite trajectories, and `actuation=NONE`. A failure is exit code 2. This command has **NOT been executed on Comma 4**, and its host unit tests use an explicit synthetic solver double. A parked synthetic pass would prove only runtime loading/solving, not live vehicle data or safety qualification.

For a diagnostic-only run on a qualified installed product, manually invoke `python3 -B -m openpilot.starpilot.longitudinal.c20_shadow --shadow-only --max-cycles 300` after the drive has started. The command subscribes to product messages and prints only allowlisted hypothetical diagnostic fields. It never starts from the product manager and cannot publish carControl or CAN. Missing native dependencies, stale messages, stock AEB/FCW, driver override or lead loss produce no computed plan; restart the process to establish a new source floor. This manual run is **not** an installation or road qualification test.
